B · Theme 01Technical foundation — my recommendations, your sign-off
12

kie.ai as the unified AI gateway

My recommendation. Vidrow's current production stack is Google Flow Labs + Higgsfield. I proposed routing the Scivo build through kie.ai instead — one bill across Veo, Kling, Suno, ElevenLabs, Nano Banana Pro, with the cheapest pricing on most of them.

WhyFlow Labs locks you to Veo + a $250/mo Ultra tier. Higgsfield is a prettier wrapper over the same models. kie.ai is the cheapest unified API for Veo Fast, Kling 3.0, Suno V4.5, and ElevenLabs simultaneously — no per-product subscription fees.
ResultStandard tier API spend lands at ~$3.70 / 60s video (vs. Flow Pro ~$3, Higgsfield Pro ~$4.70 — but with full pipeline + character consistency + final MP4 included).
+ Added · confirmed
13

Claude (latest Sonnet) as the only "thinking" model

My recommendation. Every reasoning step — script analysis, director breakdown, prompt building, character consistency, hook strategy, voice direction — runs on Claude Sonnet 4.6.

WhyBest instruction-following + structured-output reliability for the prompt-heavy work the pipeline does. Cinematic prompts and multi-turn quality gates are where Claude's quality shows through.
Coverage10/10 thinking integrations now wired on Claude.
Honest caveatThe model snapshot ID may not match the live API — audit flagged this; if it 404s, every Claude integration silently degrades to fallback. Sprint 01 fix · ~10 min (Q1 on the Roadmap).
+ Added · confirmed
14

Multi-provider engine — model swap per stage, per project

My recommendation. A registry of 28 provider definitions (35 model+provider entries) that lets you swap the video model, image model, voice, music, and LLM independently — per project or per generation.

WhyThe AI video model market changes every 2 months; you don't want to re-architect every time. The registry lets a new model (Kling O3, Veo 3.2, Sora 3) drop in with a config change.
OpenRoutes are still hardcoded to kie.ai providers — registry routing isn't wired into the generation routes yet (Roadmap C1, highest-leverage cost win).
+ Added · partial
15

Vision-AI quality checking (specifically GPT-4o Vision)

My recommendation, after you set the bar of "no fake scores." I picked GPT-4o Vision as the scorer because of its structured-output reliability for the face/clothing/body/markers rubric.

WhyVidrow's quality bar is "real vision check"; the model choice (GPT-4o Vision vs. Claude Vision vs. Gemini Vision) was mine. Roadmap C3 proposes swapping to GPT-4o-mini for ~10× cost savings if we want to.
+ Added · confirmed

Cluster 01 · Brand & client deliverablesWhat does "a brand kit" actually mean inside Vidrow?

Scivo can store brand-level fields per project today (brand name, target audience, genre, language) but there's no formal Brand Kit object. Before designing one, I need to see how Vidrow actually segments client work. Three of the most common patterns: (a) one kit per client, (b) one kit per campaign, (c) one kit per platform (Reels vs. Shorts vs. TikTok).

Q01Brand kit shape

When you start a project for Vyapar (vs. OkCredit, vs. Testbook), what do you reuse and what do you rebuild from scratch each time?

What this answer drives: whether a Brand Kit is a heavy schema (look-and-feel + voice + locked talent + LUT presets) or a light one (just brand name + tagline + 3-color palette). Wrong choice locks Scivo into one workflow.

If your answer is "we rebuild a lot"
The follow-up is: which assets do you wish you didn't have to rebuild? Those are the ones the Brand Kit should hold permanently.
Q02Output formats

Which platforms do these ~1,000 videos go to — Reels, Shorts, TikTok, in-app, broadcast — and in what mix?

What this answer drives: each platform has different aspect ratio, max length, hook conventions, and codec preferences. Scivo can pre-build per-platform templates if we know the actual mix, instead of guessing or supporting all-of-the-above.

If your answer is "mostly Reels + Shorts"
The follow-up is: do you prefer one master 9:16 master per video, or a 9:16 + 1:1 + 16:9 triple delivery?
Cluster 02 · Workflow & approvalsWho, on the Vidrow team, actually clicks "approve"?

Scivo's gating model assumes a single human-in-loop. In reality you have producers, editors, account managers, and clients — different people deserve different rights. Before adding roles, I need to see your current approval chain.

Q03Approval chain

Walk me through the approval chain for a typical client video — script approval, rough cut, final cut, client sign-off. Who owns each gate?

What this answer drives: the mapping onto Scivo's stage gates. If a client signs off on the script before keyframes start, Scivo should expose a "client preview" view that hides editor-only controls. If clients are blind until final, we don't need that view at all.

If clients see drafts
The follow-up is: do they comment in WhatsApp, Notion, Frame.io, or email? That determines the export format Scivo needs to generate.
Q04Team roles

Inside Vidrow, who would be the first three people to log into Scivo? And in what role — producer, editor, account lead?

What this answer drives: the multi-tenant schema in Sprint 04 (Roadmap, B3). I want to design user / workspace / role around actual people, not generic personas.

If you name 3 producers
Scivo's role model collapses to "owner + member". If you name 1 producer + 1 client + 1 editor we need three distinct roles with different permissions.
Cluster 03 · Scale, priorities, the next sprintIf you had to pick one win for next week, which?

The Roadmap page lists 18 concrete improvements across Speed, Quality, and Cost. I have an opinion on the order (Sprint 01 = quick quality wins, Sprint 03 = the cost engine). But the right sequence depends on which pillar you'd defend first to a client.

Q05Sequencing★ Priority

Of Speed (~17 min → ~5 min), Quality (auto-retake on every route), and Cost (~$3.70 → ~$2.40 / 60s std): which one would you defend first to a Vyapar / Testbook decision-maker?

What this answer drives: which sprint ships first. Cost wins are easiest to message externally ("90% cheaper"). Speed wins make Vidrow's internal team faster. Quality wins reduce client-side rework. They're not in conflict — just in order.

Implications
If "cost": Sprint 03 (provider registry) goes first. If "quality": Sprint 01 + 02 goes first. If "speed": Sprint 02 alone, then re-pick.
Q06Volume reality★ Priority

The 1,000-videos-a-month number — is that current real volume, projected if Scivo works, or aspirational?

What this answer drives: the architecture decisions in Roadmap B1 / B2 / B3 are sized for 1,000/mo concurrent users. If today's reality is 200/mo and 1,000 is 12 months out, Sprint 04 (multi-tenancy) can wait. If 1,000 is the next billing period, it's the gating constraint on everything else.

Implications
If 200 today: Postgres migration (B2) can wait one quarter. If 1,000 in <3 months: B2 + B3 are this month's first sprint.
Cluster 04 · Technical · assets · who hosts whatWhere do finished MP4s need to live?

Today Scivo writes outputs to local disk. That doesn't scale beyond one machine. Before Sprint 04, I need a hosting decision — Cloudflare R2, S3, GCS, or Vercel Blob — informed by where Vidrow's existing video assets already sit.

Q07Asset hosting

Where do finished client deliverables live today — Drive, Frame.io, S3, your own NAS, WhatsApp?

What this answer drives: if Drive is the destination, Scivo gets a Drive integration that auto-uploads on assembly. If S3, we share a bucket. If WhatsApp (still common in agencies), we generate a downloadable link with thumbnail preview. The destination dictates the export pipeline.

If multiple destinations
The follow-up is: per-project export route, or one global default with overrides?
Q08Voice library

Do you have a roster of preferred voice-over artists / voice clones you reuse, or do you cast fresh per project?

What this answer drives: ElevenLabs supports voice cloning. If Vidrow has 5–10 go-to voices (e.g. "Vyapar male warm Hindi", "Testbook female crisp Hindi"), we can pre-clone and let producers pick from a dropdown — same speaker across all videos for that client, automatically.

If you have a roster
The follow-up is: send 30s clean samples per voice and I'll get them clone-ready. If you cast fresh: we lean on the ElevenLabs catalog and Suno's built-in voices.
Q09Source script formats

What format do scripts come to your team in — Google Docs, Notion, raw .txt, slide decks, voice notes from clients, all of the above?

What this answer drives: Scivo's script ingest is a textarea right now. If 80% of incoming scripts are Google Docs, an "Import from Drive" button removes a copy-paste step. If a chunk are voice notes, Whisper transcription belongs in the pipeline.

Implications
If Google Docs >50%: Drive import gets prioritized. If voice notes show up: Whisper gets added to the script stage.
Cluster 05 · Commercial & relationshipHow does this engagement work going forward?

Scivo started as a build-for-Vidrow project. As it matures, the path forks: licensed exclusively to Vidrow, sold to Vidrow + other agencies (with Vidrow as flagship + co-design partner), or spun out as an independent product with Vidrow holding equity. None of these are decisions for today — but your answers to Q10 and Q11 will shape every architectural decision in Sprint 04.

Q10Engagement shape★ Priority

Is Scivo something Vidrow wants to use internally, white-label for clients, license out to other agencies, or a hybrid?

What this answer drives: every multi-tenancy decision. Internal-only = simpler schema, no need for org-level isolation. White-label = needs theming + custom domains. Multi-agency = full SaaS with billing, subscriptions, role-based access.

If "all of the above eventually"
I'll propose we design for white-label first (least lock-in) and grow into multi-tenant.
Q11Cadence + ownership

What cadence do you want to work at — weekly demos, async Slack updates, monthly check-ins? And what does ownership / IP look like?

What this answer drives: my build cycles + the right paperwork. Weekly demos = tighter scope per sprint. Monthly = bigger sprints with broader reviews. IP terms decide whether the codebase stays solo or moves into a Vidrow repo.

Implications
If "weekly": Roadmap sprints get resized to 5-day chunks. If "monthly": we batch into the four sprints already in the Roadmap.

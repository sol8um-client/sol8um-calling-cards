1. **Where MorningRise is today** — the screenshot, used NOT as an audit but as an honest snapshot. A one-page site, a clear vision, and the gap the JD names out loud. No demos, no case study, no offering yet. That is normal for week one of an agency. The Blueprint is how you get past it.
2. **The missing piece is productization** — right now any deal would be bespoke: custom scope, custom price, custom build. That is a freelancer, not an agency. A productized service = repeatable scope, repeatable price, repeatable delivery. That is the difference between an agency that closes and one that just pitches.
3. **The offering — 3 tiers:**
   - **Tier 1 — the Sprint (paid front-door).** A fixed-scope, fixed-price, fast first engagement (an AI Automation Sprint: one process automated, one to two weeks). Low-risk, gets the SME in the door, de-risks the bigger build, and pays for itself. Every productized agency needs a cheap front-door.
   - **Tier 2 — the Build.** Named, scoped, priced automation packages (lead engine, support agent, ops automation). Sold as products, not hours.
   - **Tier 3 — Managed Automation.** A monthly retainer: monitoring, iteration, new automations. Recurring revenue. The thing that makes MorningRise a business, not a project shop.
4. **The beachhead** — pick ONE vertical first (e.g. other agencies, D2C/e-commerce, or professional services like accounting/legal/clinics). Going vertical-first makes the Demo Engine and Proof Loop compound: same modules, same case studies, same language. Horizontal "we automate anything" never compounds.
5. **How it closes** — demo (interest) + proposal (close) + case study (proof) + the closer. The 4 workflows are the operating systems under this. The flywheel.
6. **Why this is not theory** — sol8um already runs this playbook. The rev-share model is the right shape: it means MorningRise and the engineer both win only when clients do. Acknowledge it founder-to-founder, no negotiation.

## 6. The 4 workflows — the productization machine (the flywheel)

These are NOT 4 client-facing automations (that shape belongs to other agency cards). They are the 4 systems that turn a zero-client agency into a repeatable closing machine. Each maps to a line in the JD.

### Workflow 01 — The Demo Engine
- **Maps to JD:** "create 1-2 high-quality demos" + "design and build demo environments"
- **Concept:** Turn ANY prospect into a tailored, working automation demo, fast. Do not hand-build 1-2 generic demos; build the system that generates a prospect-specific demo on demand.
- **Fires:** per prospect, around a discovery call (before, or as a 24h leave-behind after).
- **Inputs:** prospect's website + industry + the one process they named as a pain point.
- **Processing:** n8n + LLM pipeline pulls the prospect's public context, picks the best-fit pattern from the Build Kit, wires a working mini-demo to sample data shaped like THEIR business, renders a shareable link.
- **Outputs:** a personalized, working demo link the closer sends within 24h ("here's your invoice triage, running on your kind of data").
- **Replaces:** a week of bespoke demo-building per prospect.
- **Anchor metric:** demo turnaround (days to hours); demo-to-close rate.
- **Archetype:** event-triggered.

### Workflow 02 — Scope to Signed
- **Maps to JD:** "shape how the service is packaged and delivered" + "support early client engagements as we begin closing deals"
- **Concept:** Turn a discovery call into a productized, scoped, priced proposal in minutes. Productization = repeatable scope + price, not bespoke quoting every deal.
- **Fires:** right after a discovery call.
- **Inputs:** discovery-call notes/transcript, the prospect's stated processes, the productized service menu (from the Blueprint).
- **Processing:** LLM extracts the prospect's automatable processes, maps each to a productized package + price, flags scope risk, drafts the proposal (scope, deliverables, timeline, price, contractor terms).
- **Outputs:** a ready-to-send proposal + one-page scope doc; closer reviews and sends.
- **Replaces:** hours of bespoke proposal-writing; the inconsistency of quoting every deal differently.
- **Anchor metric:** proposal turnaround; quote-to-close consistency.
- **Archetype:** event-triggered (post-call).

### Workflow 03 — The Build Kit
- **Maps to JD:** "design and build demo environments / solutions" + "shape how the service is delivered"
- **Concept:** A library of reusable, parameterized automation modules so delivery is assembly, not rebuild. The margin engine of a productized agency.
- **Fires:** at delivery time per signed client; grows continuously.
- **Inputs:** the signed scope, the client's actual tools/accounts, the module library.
- **Processing:** delivery = pick parameterized modules (lead flow, RAG support agent, document processing, reporting), configure to the client's stack, test against their data. Each engagement either reuses modules or contributes a new one back.
- **Outputs:** a delivered, running automation; a kit that compounds — every project makes the next faster.
- **Replaces:** rebuilding from scratch every engagement (the thing that kills agency margins).
- **Anchor metric:** build time per engagement (trending down); module reuse rate; gross margin per project.
- **Archetype:** continuous / compounding.

### Workflow 04 — The Proof Loop
- **Maps to JD:** "a case study asset that we can use to start closing clients"
- **Concept:** Every delivered project auto-generates a results report + a case study. Solves the cold-start: MorningRise has no case studies; this manufactures them as a byproduct of delivery, and they feed the next sale.
- **Fires:** weekly during each engagement, and at project close.
- **Inputs:** the running automation's logs/metrics (time saved, tasks handled, errors caught), the client's baseline numbers.
- **Processing:** LLM compiles measured impact into a client-facing results report; at project close, packages the engagement into an anonymized, publishable case study.
- **Outputs:** a recurring results report that drives the retainer renewal + a case study that closes the next prospect.
- **Replaces:** the cold-start problem and the manual work of writing case studies / proving ROI.
- **Anchor metric:** case studies produced per quarter; retainer renewal rate.
- **Archetype:** reflective / weekly.

### The flywheel
Demo Engine (get them interested) -> Scope to Signed (close) -> Build Kit (deliver with margin) -> Proof Loop (turn delivery into proof) -> the proof feeds the next Demo. A self-reinforcing loop. That is the signature visual.

### Considered and dropped
- 4 client-facing automations (support bot / lead bot / doc bot / reporting bot) — that shape shows "I can build automations," not "I can build your agency." A founding-engineer role wants the second. The client-facing automations still appear, but AS the contents of the Build Kit.
- A pure AI-audit/discovery front-door workflow — folded into Demo Engine + Scope to Signed.
- A hiring / team-scaling workflow — too early for a 1-10 company.
